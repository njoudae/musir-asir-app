# مُسيّر — نظام تذاكر عبور الشاحنات

تطبيق ويب تقدمي (PWA) عربي مهيأ للجوال لإصدار تذاكر عبور الشاحنات، التحقق من المستندات، تتبع الرحلات، ومراقبة نقاط العبور من لوحة الإدارة.

## روابط العرض

- التطبيق الأساسي: [https://musir-asir-apps.vercel.app/](https://musir-asir-apps.vercel.app/)
- لوحة الإدارة: [https://musir-asir-apps.vercel.app/admin.html](https://musir-asir-apps.vercel.app/admin.html)
- دخول الأدمن التجريبي: استخدم الرمز `1234`.

## الوظائف الحالية

- دخول السائق برقم الجوال ورمز OTP، مع تكامل إنتاجي جاهز لـ Unifonic.
- زر نفاذ جاهز للربط عند الحصول على ترخيص وبيانات التكامل.
- دعم كامل للعربية والإنجليزية والأردية مع التحويل الفوري واتجاه RTL/LTR.
- حفظ بيانات الهوية الأساسية في الحساب ومنحها الأولوية على استخراج الصور.
- رفع الهوية، رخصة سير الشاحنة، وترخيص الشركة عبر الكاميرا أو الصور.
- تحليل كل مستند منفصلًا عبر OpenAI Responses API وإعادة طلب المستند الناقص فقط.
- مراجعة وتعديل البيانات المستخرجة قبل إنشاء التذكرة.
- نقاط عبور افتراضية: عقبة شعار، عقبة عسلان، وعقبة ضلع، مع نقطة مخصصة.
- إصدار تذكرة صالحة لمدة قابلة للضبط، وحفظ اللوحة والشركة والحمولة والتصاريح.
- تتبع موقع الشاحنة من المتصفح وإرسال آخر المواقع للخادم.
- لوحة إدارة تعرض الإحصاءات، الخريطة، التذاكر، الشاحنات، والمخالفات.
- تسجيل عبور لوحة شاحنة وتصنيفها: تذكرة سارية، منتهية، أو لا توجد تذكرة.

## التشغيل المحلي

يتطلب Node.js 20 أو أحدث، ولا يحتاج تثبيت مكتبات خارجية.

```bash
copy .env.example .env
npm start
```

ثم افتح:

- تطبيق السائق: `http://localhost:3000`
- لوحة الإدارة: `http://localhost:3000/admin.html`

في وضع التطوير الافتراضي يظهر رمز OTP في الشاشة وفي الطرفية، ويعمل تحليل المستندات ببيانات تجريبية. رمز الإدارة الافتراضي هو `1234`. يجب تغيير جميع هذه القيم قبل النشر.

## تفعيل SMS الحقيقي عبر Unifonic

سجّل Sender ID خدمي في Unifonic ثم اضبط:

```env
SMS_PROVIDER=unifonic
DEV_OTP_EXPOSE=false
UNIFONIC_APP_SID=your-app-sid
UNIFONIC_SENDER_ID=your-approved-sender
```

الأرقام تحول تلقائيًا إلى الصيغة الدولية السعودية `9665XXXXXXXX`. الخادم يطبق صلاحية خمس دقائق للرمز، حدًا للمحاولات، وتخزينًا مشفرًا للرمز بدل حفظه كنص.

## تفعيل تحليل المستندات عبر OpenAI

```env
AI_PROVIDER=openai
OPENAI_API_KEY=your-server-side-key
OPENAI_MODEL=gpt-5.6-terra
```

المفتاح يبقى في الخادم ولا يصل إلى المتصفح. الصور تستخدم للتحليل ولا تحفظ في قاعدة بيانات النسخة الحالية؛ الذي يحفظ هو الحقول المستخرجة داخل التذكرة.

## البيانات والتخزين

نسخة التطوير تحفظ البيانات في `data/store.json` بكتابة ذرية. هذا مناسب للتجربة المحلية فقط. للإنتاج يجب نقلها إلى PostgreSQL وتخزين أي مستندات مطلوبة للمراجعة في Object Storage مشفر، مع سياسات احتفاظ وحذف واضحة.

## الاختبارات

```bash
npm test
```

تغطي الاختبارات: OTP، إكمال الحساب، تحليل المستندات، إصدار التذكرة، التتبع، دخول الإدارة، تسجيل العبور، وإنشاء المخالفة.

## الخدمات الموصى بها للإنتاج

- **SMS داخل السعودية:** Unifonic، لسهولة تسجيل Sender ID السعودي ودعم الرسائل العربية وواجهة REST.
- **الخرائط والمسارات:** Google Maps Platform Routes API، ثم Fleet Engine عند الحاجة إلى تشغيل أسطول كبير ومتابعة تشغيلية متقدمة. النسخة الحالية تستخدم Leaflet وOpenStreetMap للعرض لتعمل دون مفتاح.
- **الخادم وقاعدة البيانات:** الخيار الأول لهذا المشروع هو Google Cloud Run مع Cloud SQL for PostgreSQL في منطقة الدمام `me-central2`، مع Secret Manager وCloud Storage خاص. عملاء الفوترة السعوديون يصلون للمنطقة عبر CNTXT وفق مسار Google الرسمي.
- **الصور:** تخزين كائنات خاص ومشفر مع روابط مؤقتة، وليس داخل قاعدة البيانات أو المتصفح.

إحداثيات نقاط العبور الثلاث في النسخة الحالية قيم أولية للعرض ويجب اعتماد الإحداثيات والـ geofences رسميًا من الجهة قبل التشغيل الميداني.

## ملاحظات إنتاجية مهمة

- تكامل نفاذ يتطلب عقدًا وترخيصًا ومسارات تحقق رسمية؛ الزر الحالي لا يدعي نجاح تحقق وهمي.
- لا تستخدم `ADMIN_PIN` كآلية الإدارة النهائية. اربط لوحة الإدارة بهوية مؤسسية وصلاحيات حسب الدور.
- التتبع في PWA يعمل ما دام النظام يسمح للمتصفح بالموقع. للتتبع المستمر الموثوق في الخلفية يلزم تطبيق iOS/Android أصلي أو غلاف مثل Capacitor مع صلاحيات الموقع المناسبة.
- قبل الإطلاق يجب تنفيذ موافقة الخصوصية، سجل التدقيق، تشفير قاعدة البيانات، النسخ الاحتياطي، وسياسة الاحتفاظ بالمواقع والمستندات.
